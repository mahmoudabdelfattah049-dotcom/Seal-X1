# إعداد وكلاء Seal X1 المجانيين

## الوضع الحالي
- المحرك: free-local-rag، يعمل بقواعد محلية واسترجاع من PostgreSQL.
- لا يستدعي OpenAI أو أي مزود نماذج مدفوعة.
- لا يحتاج OPENAI_API_KEY أو أسرار نماذج خارجية.
- Supabase Edge Function: x1-ai-agent مع JWT verification.
- قاعدة المعرفة: public.x1_ai_knowledge.
- دليل أقسام المنصة: public.x1_platform_catalog.
- سجل المحادثات والاستخدام: x1_ai_conversations و x1_ai_messages و x1_ai_usage_events.

## طريقة العمل
- QUREO: بحث في المعرفة + تحليل ساكن مبدئي للكود + قوالب شرح HTML/CSS/JavaScript.
- المساعد العام: البحث في أقسام المنصة حسب الرتبة، والفيديوهات المرسلة من الواجهة، والإعلانات والموارد المنشورة.
- لا يوجد تشغيل فعلي للكود ولا استدلال توليدي عام؛ يجب عدم الادعاء بعكس ذلك.
- جميع الطلبات تسجل صفر input/output tokens لأن المحرك لا يستخدم LLM API.

## حدود الاستخدام داخل X1
- 40 رسالة لكل مستخدم خلال 24 ساعة.
- 6 رسائل لكل مستخدم خلال 5 دقائق.
هذه حدود حماية داخل التطبيق، وليست حصة Supabase.

## تطوير قاعدة المعرفة
أضف وثائق HTML/CSS/JavaScript/QUREO إلى public.x1_ai_knowledge. اختر agent='qureo' أو 'general' أو 'both'، ولا تجعل is_published=true إلا بعد المراجعة. أضف keywords عربية وإنجليزية مترادفة لتسهيل البحث.

حدّث public.x1_platform_catalog عند إضافة قسم أو زر أو تغيير صلاحية. يجب أن يطابق section_id قيمة id الفعلية في HTML، وأن تكون allowed_roles دقيقة.

## اختبارات القبول
- أسئلة عربية عامية مع أخطاء إملائية.
- شرح HTML دلالي وخصائص CSS.
- تحليل أخطاء JavaScript الشائعة مع عدم ادعاء تشغيل الكود.
- البحث عن فيديو موجود فعلاً وفتح القسم المقصود.
- اختبار حساب طالب ومعلم موثق منفصلين.
- التأكد من عدم إظهار أقسام المعلم للطالب.
